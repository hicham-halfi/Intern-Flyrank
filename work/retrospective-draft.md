# Retrospective — draft for Hicham's personal review

AI-assisted draft based on the repository and observed runs. Review the first-person reflection before submitting; it is not evidence of hours worked or a personal learning exercise completed.

The work brought together three concrete outputs: a content-decline research case study, a working portfolio, and a small research-note agent. The original agent plan named Claude Desktop and MCP. That environment was unavailable, so the implemented version uses a bounded Python host with local Ollama inference or an explicitly approved Codex backend. The portfolio publishes the ML work and includes one browser-only calculator for planning editorial review capacity.

The most consequential change was in the ML evaluation. The original model looked encouraging under a random row split: its top-twenty precision was ninety percent, compared with sixty-five percent for the baseline. Separating clients across training and testing changed the original feature set's precision to fifty percent. That result made the evaluation design part of the project story. A high score was less useful than an explanation of which assumptions produced it and whether those assumptions matched the intended decision.

The audit also narrowed the claims. The analysis uses the thirty-thousand-row starter sample, rather than the full warehouse. Some predictors overlap the label's measurement window, and the available fields do not establish a clean future-prediction timestamp. The prior-window variant offers another retrospective comparison, but it does not remove every selection or label-construction concern. The action playbook therefore supports human review. It does not promise a traffic increase, prove causation, or authorize automatic publication.

The agent required a different kind of restraint. Its first local-model PDF run took more than nine minutes and incorrectly refused a relevant tutorial. That failure remains in the evaluation record. After explicit approval to transmit the selected PDF, the Codex path saved a grounded note. A separate full scientific PDF also produced a note with source-checked evidence. These successful runs demonstrate the narrow loop, rather than establishing reliability across arbitrary research papers.

One design decision was to make the host enforce the boundaries. The model selects document type and evidence, while the program checks paths, validates exact quotations against extracted pages, and creates a new note without overwriting an old one. Damaged numerical extraction and tutorial classification exclude experimental-result metrics. Selected excerpts reduce runtime, but also limit coverage. The external lookup path executed during evaluation, yet the arXiv request failed; the documentation reports that limitation instead of treating a tool call as a successful answer.

Three transferable practices emerge from this work. First, change the test before celebrating the score: group separation exposed an assumption the random split concealed. Second, keep a receipt for each claim: executed notebook outputs, evaluation traces and explicit user reports make the result inspectable. Third, put narrow controls around generative output: evidence checks and exclusive file creation provide stronger guarantees than asking a model to be careful. AI helped implement, test and document these systems, so that assistance belongs in the public explanation.

The useful outcome is a body of work whose successes, failures and unfinished requirements can all be inspected.
